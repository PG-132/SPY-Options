# Structure chooser

State: proposed
Created: 2026-11-04 · Updated: 2026-11-05
Specs: CHOOSE-001 to CHOOSE-007

## Problem

The README promises that, given a view and risk limits, the screener finds the structure that fits best. Nothing in the code does this yet. The measuring half (COLLECT through LEDG) is built; the choosing half is not.

## Intended behavior

The owner states the exposure they want across hypothetical future spot outcomes, and the selector finds the structure whose exposures come closest, as well as the listed contracts allow. (**Decided**, user 2026-11-05, answering A-004)

The owner's example, numbers purely illustrative: with SPY at 750, be short around 750-760; outside that range, carry less short exposure, with more bullish delta below it and more bearish delta above it. (That is roughly the delta profile of a short iron butterfly centred there; the agent's reading, not the owner's.)

- **Fit is the distance to that target.** Each candidate's exposures are compared with the stated target across the hypothetical outcomes, and the closest ranks first. "I want the most accurate exposure for what I'm betting." (**Decided**, user 2026-11-05)
- **The best achievable match is enough.** The chain won't always reproduce the target exactly; the selector returns the closest candidates and shows how far each misses. (**Decided**, user 2026-11-05)
- **Execution cost is a close second.** Among candidates that fit about equally well, the cheaper one to trade ranks first: the bid-ask paid across all legs as a share of premium. (**Decided**, owner's plan doc "SPY Options Screener Plan", 2026-09-18)
- **Nothing ranks by expected profit.** P&L appears only as a what-if (spot range, IV shifted, dates before expiry), never as a sort key. IV, IV against trailing realized, and theta per unit of gamma (which reduces to ½σ²S², so it is IV again) are context columns, never the sort. (**Decided**, README.md and the owner's plan doc)
- **The owner decides the exposure and when to hedge.** The selector shows exposures. It does not suggest hedges or flag a delta that is drifting: "I would be able to see that for myself." (**Decided**, user 2026-11-05)
- **Limits** from the owner's plan doc: a DTE window, max loss, a budget in dollars, gamma or vega, and liquidity filters (maximum bid-ask width, minimum open interest and volume). (**Decided**, owner's plan doc, 2026-09)

## Scope

Views are built in this order (**Decided**, user 2026-11-05):

1. Long premium.
2. Short premium.
3. Calendars and diagonals, which need both long and short legs.
4. Direction: verticals. The owner considers it the easiest to track.

Undefined-risk structures (short straddles and strangles) stay in the candidate set; the owner doesn't plan to trade them. (**Decided**, user 2026-11-05) Their max loss reads "unlimited", so any max-loss limit removes them, as the plan's worked example says. No margin estimate is built. (**Proposed**: the owner won't trade them, so nothing needs one.)

Out of scope for now:

- **Hedging with options** (the plan doc's hedge finder solving across strikes and expiries). It adds a layer of complication and changes the trade's structure. Hedges use SPY shares or futures. (**Decided**, user 2026-11-05)
- **Logging hedges automatically.** Delta hedges on paper trades are logged by hand in a new column of the trade's daily CSV. The owner wants this automated eventually; reading fills from Webull would need `webull.trade`, which the Boundaries in AGENTS.md forbid, so that change comes first. (**Decided**, user 2026-11-05)

Interface: a terminal command through `app.py`, like every other step. (**Proposed**; the plan doc left terminal or page open.)

## Open questions

These shape the acceptance criteria for view 1, long premium.

1. **How the target is written.** Which exposures (delta only, or also gamma, vega, theta), at which spot points (dollars, or expected moves as the rest of the screener counts distance), and as of when (now, or a date before expiry)?
2. **How distance is measured.** The units of each exposure, and how several exposures or spot points are weighted against each other.
3. **What sets the size.** The target itself (a delta in shares fixes the contract count), or a budget in dollars, gamma or vega?
4. **The search.** Which expiries (the DTE window), strikes placed by expected moves or delta, and wing widths.
5. **The fill.** Execution cost needs a fill price. Mid plus a slippage allowance is a constant, and constants come from measurements. The far side of each leg gives a measured bound.
